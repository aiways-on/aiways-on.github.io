AIways On은 사용자가 메신저에서 원하는 기능을 이야기하면, 서로 다른 역할의 AI Agent들이 요구사항 정의부터 설계, 개발, 테스트, 코드 리뷰, 보안 검토, Git Push와 PR 생성까지 개발 프로세스 전 과정을 단계별로 수행하는 AI 기반 개발 자동화 플랫폼입니다.

CHAT-FIRST MULTI-AGENT SDLC SLACK · GITHUB · K8S INCIDENT + SELF-IMPROVE

문제

The Cost of a Small Request

업무 시스템에는 기능 추가·수정 요청이 끊임없이 발생합니다. 간단한 요청 하나도 실제 반영까지 요구사항 확인 → 인터뷰 → 기존 시스템 분석 → 상세 설계 → 개발 → 테스트 → 코드 리뷰 → 보안 검토 → Git → 배포 준비를 거쳐야 합니다.

Communication Overhead

최초 요청은 대부분 구체적이지 않아, 개발자는 실제 개발보다 요구사항을 확인하고 여러 담당자와 소통하는 데 더 많은 시간을 씁니다. 작은 기능 하나에도 며칠에서 일주일 이상이 걸리고, PC·개발 환경에 접근할 수 없으면 진행이 사실상 중단됩니다.

해결 방법

AIways On은 개발 프로세스 자체를 AI Agent 중심으로 재구성합니다. 사용자는 개발 도구를 직접 다루지 않고, 채팅으로 요청하면 AI가 대화로 모호한 요구사항을 구체화하고, 이후 여러 전문 Agent가 각 단계를 이어서 수행합니다.

CORE 핵심 차별점

단순히 Claude나 ChatGPT 대화 화면을 모바일로 옮긴 것이 아닙니다. 채팅 뒤에서 요구사항 정의·설계·코딩·테스트·리뷰·보안 검토·CI가 서로 다른 역할의 Agent로 실제로 수행되고, 하나의 대화에서 시작된 요청의 컨텍스트가 개발 전 과정으로 이어지는 것이 AIways On입니다.

// SYSTEM ARCHITECTURE

아키텍처

Greenfield로 신규 구축한 모노레포(pnpm workspace). 4개 마이크로서비스가 n8n 오케스트레이션과 Kubernetes 위에서 협력합니다. 각 요청(SR)의 컨텍스트는 서비스 경계를 넘어 전 과정으로 이어집니다.

서비스 (SVC 1~4)

🖥️ Portal SVC-1 · U1~U6 공동

Next.js 16 · React 19 · TypeScript · Tailwind CSS 4 · Radix UI. Auth.js(GitHub OAuth), Drizzle ORM, Zod. 웹/API와 @kubernetes/client-node로 요청별 Pod Runner를 직접 오케스트레이션.

⚙️ Pod Runner SVC-2 · U3

Python 3.12 · FastAPI · Uvicorn. 요청(SR)마다 뜨는 ephemeral K8s Pod 안에서 Claude Code를 구동. 코딩·테스트·리뷰·Git 작업이 여기서 일어납니다.

🧠 Memory MCP SVC-3 · U6

Node 22 · MCP SDK · Drizzle. Agent에 장기 컨텍스트/메모리를 제공하는 MCP 서버. 개발 규정·시스템 컨텍스트 조회의 출입구.

🔌 Slack Gateway SVC-4 · U3

Node 22 · Slack Socket Mode. Portal과 코드·타입을 공유하지 않는 stateless 릴레이. CI에서 격리 규칙을 검사합니다.

시스템 컨텍스트

AIways On의 Agent들은 백지 상태로 코딩하지 않습니다. 조직의 개발 규정과 시스템 컨텍스트를 MCP 장기 메모리로 항상 참조하며, 하나의 요청 컨텍스트가 전 단계로 이어집니다.

CONTEXT CHAIN 컨텍스트가 이어진다

기존에는 사람이 각 단계 사이를 연결해야 했습니다. AIways On에서는 하나의 대화에서 시작된 요청의 컨텍스트(요구사항 → 설계 → 개발 규정 → 코드)가 서비스와 Agent 경계를 넘어 그대로 이어집니다. 개발 Pod는 확정된 요구사항·설계뿐 아니라 조직 개발 규정까지 로드한 상태로 코딩을 시작합니다.

개발 규정 (조직 지식 베이스)

Portal의 개발 규정 화면에서 조직의 개발 지식을 검색·등록·편집하고 개정 이력을 관리합니다. 분류별로 Agent가 참조합니다.

  • Drizzle 스키마는 유닛별 분리 · 공유 테이블·FK·마이그레이션 생성은 U1이 관리
  • Slack Gateway는 Portal과 코드·타입을 공유하지 않음 (CI 격리 검사)
